# 跑第一轮真实任务

面向维护者。目的只有一个:**让这套治理链第一次在真实工作里跑通**。

在此之前,Pillow 的每一条证据都来自单元测试和 E2E。那些证明了机制成立,
**没有证明产品可用** —— 没人用它干过活。这份文档就是补上这一环。

---

## 0. 先确认你跑的是当前代码

🔴 **`target/release/pillow.exe` 不会自动更新。** 桌面快捷方式指向它,
所以如果没重新构建,你打开的是上一次构建时的 Pillow。

```bash
cd apps/desktop && corepack pnpm tauri build --no-bundle
```

🔴 **必须走 Tauri CLI,不能用裸 `cargo build --release`。**
裸 cargo 绕过 Tauri 的配置解析,产出的二进制仍然指向 `devUrl`(开发服务器),
前端**不会被嵌进去**。这样的 exe 能开窗口,但窗口里是
`127.0.0.1 refused to connect` —— 2026-08-13 我就是这么交出去一个坏二进制的。

构建完对一下时间戳,别只看命令有没有报错:

```bash
ls -la target/release/pillow.exe
```

想确认前端真的嵌进去了(而不是只看命令成功):

```bash
grep -ac "<!doctype html>" target/release/pillow.exe
```

**1 = 嵌进去了,0 = 没有。** 🔴 界面里的中文字符串搜不到是正常的
(JS 包被压缩了),但 `index.html` 搜得到 —— 别拿"资源被压缩了"
去解释 0,那次我就是这么把证据解释掉的。

## 1. 建一个槽位

设置页 → **代理与槽位**。

新建槽位时有四种认证方式:

| 方式 | 什么时候用 |
| --- | --- |
| **API key** | 最省事。填厂商 + key 即可,预置了 10 家 |
| **OAuth 登录** | 会弹系统浏览器走授权 |
| **Grok · 登录** | 复用本机 grok CLI 已有的会话。🔴 **它不弹浏览器**,和上面那条完全不同 |
| **本机 CLI** | 扫描本机已装的 CLI |

**第一次建议用 API key** —— 路径最短,出问题也最好定位。

🔴 **角色要选「总控」(Controller)。** 只有总控槽位能在对话里直接跟你说话;
其他角色由总控在需要时调用。没有总控槽位,对话框是空的。

---

## 2. 打开一个项目

**用一个你不介意被改的目录。** 第一轮的目的是验证治理链,不是产出。

项目边界是真实的:执行器会拒绝写到项目根目录之外,
**即使权限模式开到最大也拒绝**(这点和 OpenCode / Codex 一致)。

---

## 3. 权限先别开太大

设置页 → **安全与权限**。

权限是**两个轴**,不是一个开关:

```
有效模式 = 全局允许 ∧ 项目选择
```

全局决定 Bypass **能不能用**,项目决定**用不用**。项目不能突破全局。

🔴 **第一轮请保持默认(每次询问)。** 你要看的正是审批弹出来这件事 ——
把它自动批掉,就等于跳过了这轮要验证的东西。

---

## 4. 派一个会触发审批的任务

任务本身要小,但**必须让 agent 真的动手**,否则什么都验证不到。够用的例子:

> 读一下 README,然后在项目根目录建一个 `NOTES.md`,把你读到的要点写进去。

这条会走通:**提案 → 你批准一次 → 宿主执行 → 留下收据**。

想连命令审批一起验,就再加一句「然后运行 `git status`」。

---

## 5. 这一轮要盯的东西

按重要性排:

1. **审批条真的弹出来了吗**,里面显示的路径 / 命令**对不对**
2. **批准之后,文件真的按你看到的内容写进去了吗** —— 打开文件核对,别只看 UI 说成功
3. **拒绝之后,是不是真的什么都没发生**
4. 时间线上能不能看出**谁做了什么、哪一步是你批的**
5. 关掉 Pillow 再打开,**历史还在吗**

---

## 6. 已知的边角(遇到了不用怀疑自己)

- **截断的 diff 不能直接批准。** 超过 4000 行或 256 KiB 的写入会截断,
  此时批准按钮是锁的,要把内容分页读完才解锁。这是外审 EA-04 的修复,
  不是 bug —— 你没看全的东西不该由你批。
- **命令审批里可能出现 `\uXXXX` 形式的转义。** 那是 bidi 控制字符被显式转义,
  防止参数的视觉顺序和真实 argv 不一致(EA-06)。
- **进程规则的模式里可能有不可见分隔符。** 参数含空格时,规则必须用精确编码
  才能只匹配那一条参数序列(EA-02)。对话框里会同时给出人类可读形式。

---

## 7. 出了问题怎么反馈

**把现象原样告诉总控就行,不用自己定位。** 有这几样最有用:

- 你做了什么、**期望**看到什么、**实际**看到什么
- 审批条 / 报错的截图
- 大致时间(便于对日志)

🔴 **不要自己去改设置绕过问题。** 绕过之后就查不出根因了,
而这一轮的全部价值就在于找出根因。
