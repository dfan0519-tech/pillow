# EA-04 — 截断 diff 仍可批准完整 sealed content

**状态:** complete  
**Worker:** grok2 (grok-4.6)  
**完成信号:** `EA-04-COMPLETE`

## 1. 问题摘要

外审 EA-04：用户看到的对象 ≠ 实际执行的对象。

- write content 上限 262,144 bytes。
- diff 上限 262,144 bytes / 4,000 行，超任一上限即截断。
- 渲染层只拿到 bounded unified diff + `truncated=true`。
- 批准按钮只看 `decisionLocked`，不看 `truncated`。
- 用户点批准后，executor 写入完整 `sealed.proposed_content()`。

`truncated=true` 只是警告，不能替代可审核的完整内容或 fail-closed gate。

## 2. 产品行为选择

**选择：截断时禁止批准；提供完整拟写入内容的分页审查；每一页都取回后才恢复批准。**

不选「永久禁用」：content 上限 256 KiB、行数超过 4,000 的合法写入会变成无法批准。外审第 1 条两种口子都留了；第 3 条明确要求「完整内容取回/确认后才恢复」。

审查对象是 **sealed proposed content**，不是 bounded unified diff。Diff 仍作预览；批准绑定到 proposed content 的 digest，并要求按显示上限分页取回全部页。

拒绝（Reject）在截断状态下仍可用。

## 3. 实现要点

### digest 绑定

- `BoundedDiff.content_digest` = `sha256:` + 小写 hex（与 executor `content_sha256_digest(sealed.proposed_content())` 同一算法）。
- 测试固定：digest 等于 `content_sha256_digest(proposed)`，且 **不等于** `content_sha256_digest(unified)`。
- create 大行数截断、modify 超长旧内容截断后，digest 仍是完整 proposed。
- 渲染层展示该 digest；DTO 不携带完整 `proposedContent`。

### host fail-closed

- `decide_write_proposal` 在 **消费 one-shot grant 之前** 检查：`ApproveOnce` + `diff.truncated` + 未取回全部页 → `write_truncated_unreviewed`。
- `open_write_proposal_content_page` 按 UTF-8 标量边界分页（同 4,000 行 / 262,144 字节上限）。
- 进程内会话记录已取回页；全部页取回后 `contentReviewComplete=true`。
- 决定之后清除会话。锁中毒时 fail-closed（视为未审完）。

### UI

- `WriteProposalView.diffTruncated` 为真且未审完时，批准按钮不可点；拒绝仍可。
- 「审查完整内容」按页取回并显示该 digest 对应的正文。
- `WriteDiffPreview` 在截断时同时显示 digest 与“须审查完整拟写入内容”。

## 6. 残留风险

1. **自动批准路径未纳入本次审查。** `accept_edits` / `bypass` / 已保存的 write allow rule 仍在 runtime-host 内自动决定，不读 content-review session。外审序列是「人点批准」；自动模式是另一条链，且 runtime-host 不在本单允许改动里。
2. **「取回全部页」不是阅读证明。** 同源 renderer 脚本仍可调用分页命令把会话标完（与 EA-03 的 renderer 信任模型同一层）。host 保证的是：没有取回完整 proposed 就不能 `ApproveOnce`，不是「人类逐行看过」。
3. **审查会话只在进程内存。** 宿主重启后必须重新取回；这是 fail-closed，不是静默放行。
4. **bounded unified 的旧 byte trim 仍可能切在 UTF-8 多字节中间。** 已修的是 proposed-content 分页。显示用 diff 仍只是预览，批准不绑它。
5. **「总是允许此模式」未按截断加锁。** 权限规则 crate / UI 在禁止改动范围内。截断提案上点「总是允许」仍可能落下一条后续自动批准的 write rule。
6. **完整正文只出现在分页 `text` 字段。** 一次一页、受 4,000 行 / 262,144 字节上限；拼接后用户能看到全部 proposed。Renderer 不会一次拿到超 cap 的单字段。
7. **未跑总控门禁与 E2E。** 本单禁止跑 `scripts/run-worker-gate.mjs` 和桌面 E2E。
